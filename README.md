# Храбролап: Тихая пристань — v0.9.4

## Проверки и скачивание

- `npm test`: исходные позиции трёх атак, инвентарь/экономика/миграции, 100 волн и сохранность одобренных изображений.
- `npm run qa:balance`: 12 ускоренных симуляций; это модель, а не видеозапись прохождения.
- Мобильный Chromium 390×844: анимации, реакция на урон, сменные SVG, ателье, магазин и инвентарь, сохранения, рыбалка/торговец, отдых и боссы. Скриншоты в артефактах GitHub Actions.
- Выпущенный архив `hrabrolap-v0.9.4.zip` прикладывается к **успешному** запуску GitHub Actions как артефакт, включающий HTML/CSS/JS и `art/`, `assets/`. Открывать игру нужно через HTTP-сервер из-за ES-модулей.

Предыдущие статусы QA в нижних разделах и файлах `QA-v0.*.md` — исторические; они не относятся к текущей v0.9.4.

## Запуск проекта

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

Адрес в среде с разрешённым локальным браузером: `http://127.0.0.1:8080/`. ES-модули нужно открывать через HTTP, не двойным нажатием `index.html`.

## Повторяемые проверки разработчика

```sh
npm test
npm run qa:balance
```

Для настоящего браузерного прогона на машине, где разрешены Chromium и локальный HTTP:

```sh
npm install
npx playwright install chromium
# В отдельном процессе должен работать HTTP-сервер из предыдущего раздела.
npm run qa:browser
```

`npm run qa` объединяет логику, баланс и браузер. При отсутствии браузера полный QA обязан завершиться ошибкой.

Подготовлен `.github/workflows/qa.yml`: после размещения проекта в GitHub он запускает проверки, устанавливает Chromium и прикладывает `qa/` со скриншотами к запуску Actions. **Этот workflow и браузерные тесты в данной сессии не исполнялись**; их первый успешный прогон и просмотр скриншотов остаются задачей разработчика. Репозиторий и публикация игры не создавались.

Требование проверять каждое изменение закреплено в `AGENTS.md`. Техническое тестирование выполняет разработчик; пользователь утверждает художественные и игровые решения.

## Предметы и лут — v0.9.3 (16.10.2026)

- Добавлены **10 моделей SVG-мечей** (железный, лесная палка, рыбий позвоночник, лапа паука, костяной, слизневый, лунный, лесной, паутинное жало, сумеречный демон) и **10 покупаемых комплектов SVG-брони**, плюс состояние без брони.
- **Паутинная броня**: 300 монет и 6 единиц паутины. **Броня из костей и слизи**: 550 монет, 5 костей и 5 слизи.
- В обычных встречах вероятность появления паука 30%. На исходных регулярных паучьих слотах при отсутствии случайного паука появляется скелет. С каждого паука после победы падает 1 паутина, со скелета 1 кость, со слизня 1 слизь. Личинка и гриб дают листья, жук — хитин, призрак — эссенцию.
- Материалы сохраняются в инвентаре. Рецепты показывают собранное и требуемое количество, покупка проверяет оба вида ресурсов и списывает их атомарно.
- Сохранения v1–v3 мигрируют; новый формат v4 сохраняет лут и текущий вид врага. Модель кота `art/hero/bare-kitten.svg`, старые PNG-кадры, параметры трёх атак `ATTACKS` и ранее утверждённые мечи/доспехи **не менялись**.
- Исторические отчёты QA относятся к старым версиям. Нужна проверка новой ветки через GitHub Actions, в том числе мобильный Chromium.

## SVG-ателье и синхронизация слоёв — v0.9.4 (16.10.2026)

- Предпросмотр `equipment-preview.html` на телефоне: 3 типа атак и реакция на урон, по 6 кадров, любой из 10 мечей и 10 комплектов брони. Технический просмотр использует текущую игровую SVG-модель кота (это **не** конвертация пользовательских референсных изображений в спрайты).
- Новая таблица `equipment-rig.mjs` содержит отдельные позы броневого SVG-слоя и 6 поз реакции на урон. Исходный `ATTACKS` в `game.mjs` сохранён без изменения координат; тест сравнивает его с эталоном в модуле.
- Для урона добавлен конечный автомат реакции из шести коротких кадров со сбросом при скрытии вкладки и возрождении. Во время реакции меняется лишь положение готовых слоёв, но не сам кот.
- Текущая версия игры пока не содержит раздельных точных рисованных SVG-слоёв для лап/шлема каждой новой брони и не заменяет полностью базовый рисунок на авторские шесть отдельных спрайтов; эти художественные задачи требуют отдельной приёмки.
- Результаты этой версии следует проверять по новому запуску CI (Node + мобильный Chromium), а не старому QA v0.9.3.
