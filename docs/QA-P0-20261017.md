## 3. Внедрённые защитные меры

### CI-SAFETY — техническая часть сделана
- `.github/workflows/qa.yml`: `permissions: contents: read`, нет шагов `git push`, создания тега `v0.9.7` и автоматического коммита графики после тестов.
- Проверка утверждённых оригиналов `git diff --exit-code -- assets/canonical/ art/approved/ tests/locked-art-shas.json`.
- Убрано генерирование уже принятых кадров «Лесного стража» в CI; исходная метка `assets/clean/forest_guardian/refined-v2.txt` существует в репозитории. Перед упаковкой проверяется, что runtime-изображения и связанные файлы не были изменены скриптами тестирования.
- Артефакты ZIP и `qa/` всё ещё собираются/публикуются **только как downloadable GitHub Actions artifacts**, без автоматического релиза/коммита ассетов.
- **Оставшаяся косметическая задача:** версия `v0.9.7` сохранена в исторических названиях ZIP/метаданных; менять её следует в согласованном релизном PR, не вместе с P0.

### SAVE-MIGRATE — ключевой старый случай исправлен
- В `game.mjs` миграция старой законченной 700-волновой кампании теперь игнорирует сохранённый старый финальный бой и начинает новый бой на 701-й волне.
- `save-backup.mjs`: проверка формата, версии сохранения, обязательных полей, нормализация данных через `validateProgress` и `restoreFight`.
- `save-manager.html` / `save-manager.mjs`: **отдельная** мобильная страница — скачать JSON на старом адресе, проверить/показать файл на новом, после явного подтверждения импортировать.
- Новое сохранение не перезаписывается **при выборе файла**; некорректный JSON, неизвестная версия и чрезмерный размер отклоняются до записи.
- Контексты браузера/порты разделяют `localStorage`; автоматического «волшебного» переноса между 8080 и 8090 нет. Сначала создать копию на исходном порту.

### QA-тесты
- `tests/save-backup.test.mjs` включён в `npm test` — миграции старого финала 100 и 700, инвентарь/экипировка/валюта, пределы, отклонение повреждённого файла.

## 6. Как запустить и безопасно перенести прогресс

```bash
cd ~/hrabrolap-new
git pull --ff-only origin main
python -m http.server 8090 --bind 127.0.0.1
```

Страница для скачивания из **старого** `8080`: `http://127.0.0.1:8080/save-manager.html`.

Страница для загрузки на **новом** `8090`: `http://127.0.0.1:8090/save-manager.html`.

Прежде чем менять порт, надо, чтобы старый сервер ещё был доступен. **Не выполнять «Сброс» и не удалять localStorage.** Если старый порт уже закрыт, можно снова запустить сервер на 8080 с тем же кодом, скачать JSON и затем открыть 8090.
