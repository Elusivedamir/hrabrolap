# Правила разработки и QA «Храбролапа»

Продолжать исходный проект. Не создавать замену игры. Ассеты, внешность, фоновые иллюстрации и утверждённую анимацию менять только по прямому указанию Дамира. Изменения баланса и художественные решения требуют его утверждения. Исправления программных ошибок и техническое тестирование выполняет разработчик.

После каждого изменения:

1. `npm test` — синтаксис, ядро, регрессии, путь 1–100, сохранение состояния, целостность ассетов.
2. `npm run qa:balance` — двенадцать сценариев, сохранить JSON и CSV, указать политику покупок, ограничение времени и факт ускоренной симуляции.
3. `npm run qa:browser` — в разрешённой среде с Chromium/Playwright и запущенной игрой. Проверить мобильный экран, три атаки, смену SVG, магазин/инвентарь, 8 монстров и короны, рыбалку/торговлю, дом/возрождение, реальные localStorage reload, ошибки JavaScript. Просмотреть полученные скриншоты.
4. Повторить затронутые проверки после исправлений, обновить README и QA-отчёт, затем собрать ZIP.

Не ставить общий PASS, если браузер не запускался. Подготовленный, но не запущенный тест — NOT RUN. Не выдавать анализ кода, симуляцию или статическую картинку за игру в браузере. Если браузер блокируется, назвать точную причину, сохранить доступные результаты и предложить разрешённый способ запуска. Не обходить политики среды.

Браузерный стенд и CI из v0.8.1 подготовлены, но в текущей сессии НЕ выполнены. Первое успешное исполнение и визуальная проверка обязательны до утверждения их работоспособности. Не просить пользователя проводить техническую проверку; его участие — художественная и игровая приёмка.
